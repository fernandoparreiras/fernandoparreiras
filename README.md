## Trustyu Forge — Engineering Harness

[Trustyu Forge](https://forge.trustyu.ai) is the human-directed engineering harness around AI-assisted delivery. It does not promise that generated code becomes production software automatically. It makes intent, context, execution, verification, evidence, authority, and outcomes traceable.

```text
SPEC → EXPLORE → PLAN → RED → IMPLEMENT → GREEN → VERIFY → VERDICT
```

| Harness layer | Public description |
| --- | --- |
| Knowledge and intent | Versioned ADRs, specifications, standards, runbooks, skills, and release contracts |
| Isolated execution | Named ownership, branches/worktrees, task sandboxes, capability boundaries, and least privilege |
| Verification | Contract-first tests, affected checks, smoke tests, SAST, CVE/secret gates, evals, and independent evidence |
| Provenance | Source-bound subjects, artifact identity, receipts, evidence bundles, and explicit limitations |
| Governance | Risk-proportional profiles, gate lifecycle, scoped overrides, rollback, and human verdicts |
| Delivery integrity | CI, merge, deployment, public behavior, operation, and outcome remain separate states |
| Learning | Measured reliability, cost, failure modes, and durable feedback without invented productivity multipliers |

FORGE 3.2 adds Brownfield & Consolidation for systems that must be preserved, integrated, redesigned, or retired. FORGE 3.3 adds verifiable governance and delivery integrity. The current integrated program is Alpha; each mechanism carries its own implementation, verification, and operating evidence.

## AI Architecture

### Agentic systems and workflows

- **Hub Agents:** Python, FastAPI, Clean Architecture, LangGraph, PostgreSQL/pgvector, Redis/Arq, tenant isolation, pluggable channels, and product-specific personas and tools.
- **AI Works:** TypeScript/Fastify control and data planes, Next.js authoring, Temporal durable supervision, Go/Zigflow workflow execution, and workerd-isolated Functions.
- **Compiled contracts:** Agents and Workflows become versioned `openworkflow/v1` artifacts; Functions execute exact immutable targets with authorization and policy revalidation.
- **Effects:** idempotency keys, tool journals, approvals, and effect receipts make retries explicit; uncertain external effects stop for reconciliation.
- **Human authority:** a model can propose or execute within policy, but external, irreversible, and production decisions remain with an authorized person.

### LLM model strategy

Trustyu does not relabel third-party foundation models as proprietary models. The architectural asset is governed selection and routing:

- Hub Agents uses an `LLMFactory` to route by use case and capability;
- AI Works maintains product-specific model registries, provider protocols, and frozen run policies;
- Anthropic, OpenAI, and Google models can be compared for different tasks;
- promotion considers eval quality, latency, cost, data risk, fallback, and observability;
- model IDs stay in product authorities instead of drifting across documentation;
- a provider listed here is not automatically enabled for every product, tenant, or dataset.

### Durable memory and context

Durable memory is governed evidence, not an unlimited transcript dump:

- authoritative records are separated from rebuildable full-text/vector indexes;
- writes are idempotent and coordinated by durable workflows;
- retrieval is permission-revalidated, bounded, and purpose-aware;
- claims preserve provenance, confidence, limitations, feedback, and invalidation paths;
- content-addressed artifacts and explicit heads prevent silent replacement;
- retention and purge are storage contracts;
- private recovered content is not copied into logs or durable traces by default.

AI Works platform memory and NEEDYU context/memory explorations remain separate bounded contexts. Similar concepts do not imply a single shared production service.

### Evaluations, typed decisions, and Jev

- Evals pin the candidate, dataset, harness, judge, rubric, and policy snapshot.
- Online observations and offline evaluation executions remain distinct.
- Missing evidence or an unavailable judge does not silently become approval.
- Overrides require scoped authority and remain auditable.
- Typed decision ports constrain a responder to declared options instead of granting open system authority.
- **Jev** is an external typed-decision responder used in scoped, policy-gated and shadow-mode flows. Its use depends on consent, data minimization, fallback, frozen policy, and provenance; it is not a universal runtime dependency.

### Trustyu Score

Trustyu Score is currently **human-led and AI-assisted**, not an autonomous auditor. Its deterministic Core v3 supports:

- a 0–100 technical score across four dimensions and eleven pillars;
- explicit `unknown` and `not_observed` states instead of turning missing evidence into zero;
- safety caps and applicable-coverage requirements;
- three report tracks: Technical, Product, and Market;
- typed evidence, risks, impact, priorities, limitations, and remediation roadmaps.

The target source-bound runtime, specialized product agents, Evidence Plane, and client portal remain review-gated. No claim of scientific validation, certification, autonomous availability, or FORGE attestation is made here.

Read the [full public architecture map](docs/trustyu-ai-architecture.md) for the detailed product, runtime, memory, evaluation, stack, and disclosure boundaries.

## Multi-Agent Engineering Model

I use AI agents as a bounded execution layer:

- repository instructions and ADRs keep decisions outside transient chat memory;
- one task, one owner, one branch/worktree, and explicit handoffs reduce collisions;
- contract-first RED/GREEN/VERIFY cycles make progress reviewable;
- model output, test result, reviewer signal, merge, deploy, and operation are distinct;
- human and AI review signals complement rather than replace engineering judgment;
- tools and egress follow capability boundaries and least privilege;
- privacy-safe traces make agent behavior debuggable without logging customer content;
- secrets, customer evidence, and private topology remain outside the public profile.
